# Варианты пресета: один агент, список моделей, приоритет пулов

Проект (только предложения, код не менялся). Рабочая копия: `/Users/ra/DevProjects/LLM/pi-plugin-cc`,
ветка `compatible-pi`. Замеры сняты 2026-09-18 на хосте `ra`, конфиг — `<дом CC>/pi/config.json`
(20 пресетов, пулы `zai 7 · deepseek 7 · vllm 1`).

Задача пришла от владельца одной фразой: «в пресетах для каждой модели приходится дублировать
агентов; хочется агент со списком моделей и приоритетом пулов, и чтобы при занятом пуле брался
следующий; плюс для локальной vLLM не хватает `samplingParams`».

## 0. Факты, из которых следует весь дизайн

1. **Дублирование замерено: 20 пресетов при ~7 логических ролях.** Три варианта
   `python-developer-{zai,deepseek,local}` отличаются ровно четырьмя полями — `model`,
   `sandbox.profile`, `thinking`, `tags` (+хвост `description`) — при тридцати строках
   байт-в-байт одинаковых: `systemPrompt`, `appendSystemPrompt`, весь блок `PI_HOOKS` с
   `GIT_CONFIG_*`, `mounts`, `skills`, `timeoutMs`, `git`. Правка общей части сегодня — это
   правка в трёх местах, и расходятся они молча.
2. **Пул привязан не к модели, а к профилю песочницы.** `pi-companion.mjs:1178-1194`:
   лимит живёт в `concurrencyPools[concurrencyGroup]`, профиль называет группу
   (`agent` → `zai`, `agent-deepseek` → `deepseek`, `agent-dind-vllm` → `vllm`). Поэтому
   «приоритет моделей» и «приоритет пулов» — одна сущность: приоритет **вариантов**
   (модель + профиль + thinking), а не два независимых списка.
3. **Ожидание слота уже реализовано и уже измеряется.** `awaitSandboxSlot` возвращает
   `{waitedMs, slots, release}` (`sandbox.mjs:733`). Сегодня прогон в этой точке ЖДЁТ.
   Предлагаемое поведение — на развилке «ждать или взять следующий вариант» — врезается ровно
   сюда, и `waitedMs` даёт готовый критерий для порога.
4. **`fallbackPreset` знает только пайплайн, не companion.** Поле читает
   `llm-workflow/plugins/feature-workflow/skills/_shared/scripts/pi-health.sh:107`; в
   `pi-plugin-cc` его не читает никто. То есть фолбэк сегодня живёт снаружи и работает по
   пресетам, а не по вариантам.
5. **`model2` в `python-developer-deepseek` — рудимент** (подтверждено владельцем 2026-09-18).
   Companion его не читает. Удалить вместе с миграцией конфига.

## 1. Часть A — варианты пресета с приоритетом

Порядок в списке = приоритет. Общая часть пишется один раз, вариант несёт только различия.

```json
"python-developer": {
  "description": "Python-задача целиком: прод-код, юнит-тесты, гейты, коммит",
  "systemPrompt": "developer",
  "appendSystemPrompt": ["@<дом CC>/pi/prompts/stack/python.md"],
  "mounts": ["…"], "skills": ["…"], "git": {"…": "…"}, "timeoutMs": 10800000,
  "variants": [
    {"model": "zai-coding-cn/glm-5.3-flash", "sandbox": {"profile": "agent-dind"},      "thinking": "low"},
    {"model": "deepseek/deepseek-v4-flash",  "sandbox": {"profile": "agent-deepseek"},  "thinking": "low"},
    {"model": "vllm/Qwen3.8-27B",            "sandbox": {"profile": "agent-dind-vllm"}, "thinking": "off", "tags": ["local"]}
  ]
}
```

**Слияние:** вариант перекрывает поля базы поверхностно, кроме `env`/`mounts`/`skills`/`tags`,
которые складываются. Причина различия — в базе они списки оснастки, а не значения: вариант
должен добавлять монтирование, а не заменять весь набор.

**Выбор варианта на выдаче:**

1. идти по списку сверху вниз;
2. вариант пропускается, если его пул занят **и** ожидание превысило порог, либо если состояние
   здоровья объявляет его недоступным (квота, отказ провайдера);
3. все варианты пропущены → прежнее поведение: ждать первый по приоритету, печатая, чего ждём;
4. `--model` и явное имя варианта продолжают адресовать вариант напрямую — иначе отлаживать
   конкретную модель станет нечем.

**Совместимость имён обязательна.** Имена пресетов — часть контракта скиллов `llm-workflow`
(брифы, `route-agent.sh`, тексты `pi.md`). Старые `python-developer-zai` остаются алиасами на
`python-developer` + вариант; резать их разом нельзя.

**Цена:** слияние базы и варианта ~40 строк; выбор варианта на `awaitSandboxSlot` ~30; алиасы ~20;
миграция конфига — разовый скрипт, 20 пресетов → 7.

## 2. Часть B — `samplingParams` сквозь прокси

Отдельная, меньшая, но независимая правка: **сегодня `samplingParams` до песочницы не доходит.**

pi поддерживает поле с 0.85.0 (`docs/models.md#sampling-parameters`, PR #7568): free-form объект,
вливается в тело запроса после полей pi, ключи выигрывают; применяют только OpenAI-совместимые
API — vLLM как раз такой. Но агент в песочнице читает **не** хостовый `models.json` агента pi:

- при `credentialProxy` монтируется сгенерированный файл (`sandbox.mjs:461-471`,
  `writeProxyModels` — `sandbox.mjs:698`), а хостовая таблица не копируется сознательно;
- таблицу строит `credential-proxy.mjs` и переносит поля модели **белым списком**: `id`,
  `reasoning`, `contextWindow`, `maxTokens`, `input`, `cost` — две копии, строки ~212-219 и
  ~455-466. `samplingParams` нет ни в одной;
- проверено фактом, а не чтением: у бегущего контейнера
  `/pi-agent/models.json` ← `<tmp>/pi-companion/auth/models-run.<pid>.json`, внутри провайдер
  `sandbox`, модель `agent-model` (`MASKED_MODEL`, `credential-proxy.mjs:348`) и ровно эти поля.

**Правка:** добавить `samplingParams: real?.samplingParams ?? undefined` в оба места переноса.
Поле не несёт ни адреса, ни ключа, поэтому маскировку не ослабляет — в отличие от `baseUrl`,
который прокси прячет намеренно.

**Цена:** две строки плюс кейс в наборе. **Без части A работает самостоятельно** — делать можно
первой.

## 3. Что решить до реализации

| Вопрос | Почему не деталь |
|---|---|
| Порог «пул занят» — сразу пропускать или ждать N секунд? | Пропуск на первой же занятости уводит быструю модель на медленную при мгновенно освобождающемся слоте; вечное ожидание — то, что чинится этой задачей. `waitedMs` уже есть, нужен порог |
| Приоритет глобальный или на пресет? | Предлагается на пресет (порядок `variants`): у ревью и у исполнения разная цена ошибки, один глобальный список их смешает |
| Что делать с `vllm 1` | Пул в один слот при приоритете «локальная первой» сериализует весь флот. Локальная модель уместнее последней — или с порогом ожидания 0 |

## 4. Что придётся поправить в `llm-workflow`

Задача двухрепозиторная, и вторая половина не бесплатна:

- **`pi-health.sh` ведёт состояние ПО ПРЕСЕТУ** (шапка файла: «Состояние ведётся по пресету, а не
  по провайдеру»). При схлопывании состояние обязано вестись **по варианту**, иначе мёртвый
  deepseek положит весь `python-developer` целиком — то есть ровно тот отказ, который задача
  и должна лечить.
- **Это по-настоящему закрывает B-30** (`llm-workflow/docs/BACKLOG.md`): пул deepseek без баланса
  (`402 Insufficient Balance`), `classify` его не распознаёт, задача уезжает туда и умирает за
  6 секунд. Лечение сегодня ручное — «выдавай на zai».
- **Снимается противоречие в скилле `developer`.** Скилл требует: «модель и провайдер за пресетом —
  дело конфигурации pi, а не скилла, `--model` не ставь», — а имя `python-developer-zai` называет
  провайдера прямо в контракте. После схлопывания скилл называет роль и стек, конфиг решает, чем
  исполнять.
